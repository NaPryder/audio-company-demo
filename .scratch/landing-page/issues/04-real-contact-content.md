
และมีบรรทัดที่ design เขียนกำกับตัวเองไว้ว่า `Privacy Notice - เพิ่มลิงก์ก่อน production`.

งานที่ต้องทำ (ผู้ใช้เป็นคนให้ข้อมูล agent ทำแทนไม่ได้):

1. อีเมล / เบอร์โทร / LINE ID / ลิงก์ Facebook / Instagram / TikTok ตัวจริง
2. ค่า `LEAD_RECEIVER_EMAIL` ที่จะให้ Resend ยิงไปหา
3. โดเมนที่จะใช้ (ต้อง verify กับ Resend ก่อนส่งเมลได้)
4. Privacy Notice - มีหน้านี้อยู่แล้วไหม หรือต้องเขียนใหม่ หรือ v1 ตัดลิงก์ทิ้ง
5. ชื่อบริษัทจดทะเบียน + ข้อความ copyright ใน footer
6. copy ในหน้าที่ Figma เขียนไว้ - ใช้ตามนั้นได้เลย หรือรอลูกค้าส่งข้อความจริงมา

**ผลลัพธ์ที่ต้องได้**: ค่าจริงทั้งหมด ระบุด้วยว่าอันไหนอยู่ใน `content/company.ts` อันไหนอยู่ใน env.

## Progress (ส่วนที่ทำเองได้ - รอข้อมูลจากผู้ใช้จึงจะปิดได้)

### ตัดสินแล้ว: อะไรอยู่ env อะไรอยู่ content

**env** - เฉพาะความลับกับค่าที่เปลี่ยนตาม environment:

| ตัวแปร | ใช้ทำอะไร |
|---|---|
| `RESEND_API_KEY` | ความลับ |
| `RESEND_FROM_EMAIL` | ผู้ส่ง ต้องอยู่ใต้โดเมนที่ verify กับ Resend แล้ว |
| `LEAD_RECEIVER_EMAIL` | ปลายทางที่ Lead จะไปถึง (ผู้ใช้ระบุไว้ใน Q10) |
| `NEXT_PUBLIC_SITE_URL` | ใช้ทำ canonical + OG url |

**content** (`src/features/contact/data.ts`) - ข้อมูลติดต่อที่แสดงบนหน้าเว็บ: อีเมล, เบอร์โทร, LINE, Facebook, Instagram, TikTok, ชื่อบริษัท.

เหตุผลที่ไม่ยัดลง env ทั้งหมด: ค่าพวกนี้เป็น**เนื้อหาที่คนเห็นบนหน้าเว็บ** ไม่ใช่ config ของ environment.
ถ้าอยู่ใน env จะไม่มีประวัติใน git, คนแก้เนื้อหาแก้เองไม่ได้, และ preview กับ production จะเพี้ยนกันได้โดยไม่มีใครรู้.
`LEAD_RECEIVER_EMAIL` ต่างออกไปเพราะมันคือ**ปลายทางการส่ง** ไม่ได้แสดงบนหน้าเว็บ - อยู่ env ถูกแล้ว.

## Answer

### 1. แหล่งข้อมูลติดต่อ = env ทั้งหมด (ผู้ใช้ตัดสิน)

ผมเสนอให้แยกเป็น content file ผู้ใช้เลือก env ทั้งก้อน. บันทึกตามนั้น.

⚠️ **ผลที่ตามมาที่ต้องรู้**: หน้า Home เป็น static page ดังนั้น `process.env` ถูกอ่าน **ตอน build**.
แก้เบอร์โทรหรือ LINE ID ทีนึง = ต้อง redeploy ทุกครั้ง แก้ผ่านหน้า Vercel เฉย ๆ ไม่พอ.
เขียนไว้ใน checklist ของ ticket 08 แล้ว.

**ห้ามใช้ prefix `NEXT_PUBLIC_` กับตัวแปรกลุ่ม contact** - section Contact เป็น server component อ่าน `process.env` ตรงได้เลย.
ใส่ `NEXT_PUBLIC_` จะทำให้ค่าถูกฝังลง client bundle โดยไม่จำเป็น ได้ผลเท่ากันแต่ bundle ใหญ่ขึ้น.

### 2. รายการ env ทั้งหมด (ค่า mock)

```bash
# .env.example

# --- Resend ---
RESEND_API_KEY=re_mock_000000000000000000
RESEND_FROM_EMAIL=noreply@example.com
LEAD_RECEIVER_EMAIL=team@example.com

# --- Site ---
NEXT_PUBLIC_SITE_URL=http://localhost:3000

# --- Contact (server-side only, ห้ามใส่ NEXT_PUBLIC_) ---
COMPANY_NAME=บริษัท ดิ ออริจิน บีท จำกัด
CONTACT_EMAIL=info@example.com
CONTACT_PHONE=021234567
CONTACT_LINE_ID=@originbeat
CONTACT_FACEBOOK_URL=https://facebook.com/originbeat
CONTACT_INSTAGRAM_URL=https://instagram.com/originbeat
CONTACT_TIKTOK_URL=https://tiktok.com/@originbeat
```

validate ด้วย Zod ที่ `src/lib/env.ts` แล้ว export object เดียวออกไปใช้ - ถ้าลืมตั้งค่าบน Vercel จะพังตอน build ไม่ใช่ตอนลูกค้ากดส่งฟอร์ม.

### 3. `[ชื่อลูกค้า]` บนการ์ดผลงาน

**ซ่อน field ไปก่อน**. งานติดตั้งห้องประชุมมัก NDA - ใส่ชื่อไปก่อนแล้วมาลบทีหลังคือความเสี่ยงที่ไม่จำเป็น.
type ของ `Project` ยังมี field `client` แบบ optional ไว้ (ดู ticket 06) ค่อยเปิดเป็นราย ๆ เมื่อได้อนุญาต.

### 4. ร่างข้อความแนะนำบริษัท

แทนที่ `[ข้อความแนะนำบริษัท] อธิบายขอบเขต...` ใน Company Intro.
ความกว้าง 638px / 18px / line-height 30 → ประมาณ 3-4 บรรทัด.

```
เราออกแบบ จัดหา ติดตั้ง และทดสอบระบบเสียงและภาพ สำหรับห้องประชุม ห้องอบรม
และพื้นที่ใช้งานจริง โดยเริ่มจากลักษณะของห้องและวิธีที่คุณใช้งานจริง ก่อนเลือกอุปกรณ์
ทีมงานดูแลตั้งแต่การวางระบบจนถึงการส่งมอบและแนะนำการใช้งาน
เพื่อให้เปิดห้องแล้วใช้งานได้ทันที
```

แบบสั้นกว่า ถ้าอยากได้ 2 บรรทัด:
```
เราออกแบบ จัดหา ติดตั้ง และทดสอบระบบเสียงและภาพ โดยเริ่มจากลักษณะของห้อง
และวิธีที่คุณใช้งานจริง เพื่อให้เปิดห้องแล้วใช้งานได้ทันที
```

เขียนให้เข้ากับโทนของหัวข้อ `เชื่อมเทคโนโลยีให้ใช้งานง่ายและเหมาะกับพื้นที่` - เน้นวิธีทำงาน ไม่ใช่คำโฆษณา.

### 5. Privacy Notice

**ต้องมี route เพิ่ม 1 หน้า** - `src/app/privacy/page.tsx`.
Q7 ตัดเหลือ Home หน้าเดียว แต่ลิงก์ Privacy ต้องมีปลายทาง. หน้านี้เป็นเอกสารข้อความล้วน ไม่มี design ไม่ต้องดึงจาก Figma - ใช้ Header/Footer เดิม.
`PRIVACY_NOTICE_URL` จึงไม่ต้องเป็น env ใช้ `/privacy` ตรง ๆ.

ร่าง (อิงตาม PDPA):

```markdown
# ประกาศความเป็นส่วนตัว

ปรับปรุงล่าสุด: [วันที่]

## ข้อมูลที่เราเก็บ
เมื่อคุณส่งแบบฟอร์มติดต่อ เราเก็บ ชื่อผู้ติดต่อ อีเมล เบอร์โทรศัพท์
ชื่อบริษัท (ถ้ากรอก) และรายละเอียดความต้องการที่คุณระบุ

## วัตถุประสงค์
เพื่อติดต่อกลับและประเมินแนวทางการติดตั้งระบบตามที่คุณสอบถามเท่านั้น
เราไม่ใช้ข้อมูลนี้เพื่อการตลาดอื่น และไม่ขายหรือส่งต่อให้บุคคลที่สาม

## การเก็บรักษา
ข้อมูลจากแบบฟอร์มถูกส่งเป็นอีเมลมายังกล่องจดหมายของทีมงาน
เราไม่ได้จัดเก็บข้อมูลนี้ในฐานข้อมูลของเว็บไซต์
ผู้ให้บริการที่เกี่ยวข้องกับการส่งอีเมลและการโฮสต์เว็บไซต์
อาจเก็บบันทึกการทำงานตามนโยบายของผู้ให้บริการนั้น

## ระยะเวลา
เราเก็บอีเมลที่ได้รับไว้เท่าที่จำเป็นต่อการติดต่อและอ้างอิงงาน
และลบเมื่อไม่จำเป็นอีกต่อไป

## สิทธิของคุณ
คุณมีสิทธิขอเข้าถึง ขอสำเนา ขอแก้ไข ขอลบ หรือขอให้ระงับการใช้ข้อมูลของคุณ
รวมถึงถอนความยินยอมได้ตลอดเวลา โดยติดต่อเราตามช่องทางด้านล่าง

## ติดต่อ
[ชื่อบริษัท]
อีเมล: [อีเมลบริษัท]
โทร: [เบอร์โทรศัพท์]
```

⚠️ นี่เป็น**ร่างสำหรับให้ผู้มีคุณสมบัติตรวจก่อนใช้จริง** ไม่ใช่คำแนะนำทางกฎหมาย.
ส่วนที่ผมเขียนให้ตรงกับความจริงของระบบแล้วคือ "ไม่ได้จัดเก็บในฐานข้อมูล" (ตาม Q9) และ "ส่งเป็นอีเมลถึงทีมงาน" (ตาม Q10).

### 6. copy ที่ต้องแก้เพราะเป็นเท็จ

Contact description เดิม: `ส่งข้อมูลเบื้องต้นหรือแนบแบบห้อง เพื่อให้ทีมงานติดต่อกลับและช่วยประเมินแนวทางต่อไป`
→ ตัดคำว่า "หรือแนบแบบห้อง" ออก (Q4 ตัด file upload):
```
ส่งข้อมูลเบื้องต้นเกี่ยวกับพื้นที่ของคุณ เพื่อให้ทีมงานติดต่อกลับและช่วยประเมินแนวทางต่อไป
```

→ อยู่ใน checklist ของ ticket 08
